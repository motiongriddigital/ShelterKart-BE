# Security review of the API, October 2026

Board item SHEL-24. Base: main at 76bef7d (the import commit). Reviewed on branch chore/security-review. Written 2026-10-27.

Confirmed findings are filed as bug items in the Control Room project `shelterkart`, each part of SHEL-24. Suspected findings are listed here only. Severity uses the board's meaning (S1 production down or users cannot do the core task, S2 production degraded or a shared environment down, S3 limited defect or no data loss, S4 cosmetic or dev-only), followed by what an attacker gains.

Already known and not repeated: SHEL-28 (payment webhook crashes on a non-JSON content type), SHEL-29 (malformed or oversized JSON returns 500), SHEL-30 (PUBLIC_BASE_URL and ALLOWED_ORIGINS), and `POST /api/investigate/{ref}/contact` needing no token.

## Summary

- 16 confirmed findings: 3 at S2, 10 at S3, 3 at S4 (SHEL-31 to SHEL-46).
- 9 suspected findings, listed below.
- `npm audit`: 0 vulnerabilities, production and dev (87 production dependencies, no dev dependencies).
- No secrets in the repository. SQL is parameterised everywhere. HTML escaping of report content, disputes and developer replies is sound; one gap in URL schemes (SHEL-40).
- Three one-request ways to stop the process: SHEL-31 (new), SHEL-32 (new variant of SHEL-28), and SHEL-28 itself.

## Scope and method

Order followed: server.js and its engines, the SSRF guard and untrusted-content handling, secrets and logging, CI and container files, dependencies.

How:

1. Read server.js in full (1,616 lines, about 60 routes) and the modules behind the routes: engine/access.js, botguard.js, razorpay.js, mor.js, reviews.js, reportPages.js, dossierHtml.js, dossier.js, dossierBrief.js, investigator.js, searchLane.js, documents.js, delivery.js, research.js (purge, caps), persistence.js, jobStore.js, pdf.js; pricing/quote.js and store.js; payments/refunds.js; connectors/egress.js and untrusted.js; admin.html (rendering only).

No AI, payment or delivery credentials were set, so no request left the machine. All processes and the database were stopped afterwards.
3. Reproduced every confirmed finding with commands against the running server or the modules directly; the commands and outputs are in each board item and summarised below.
4. Fuzzed 17 body-taking routes with 14 hostile values each (types, NUL bytes, objects with a throwing `toString`), with a supervisor that restarts the server and records which request killed it.
5. Rendered the full report, preview and sample pages with every free-text string poisoned with markup, and with every URL field set to a `javascript:` URL.
6. Read `.github/workflows/ci.yml` on main. The Dockerfile, docker-compose.yml and release workflow are not on main; they are in PR #3 (feature/deployment-pipeline) and were read for context only.
7. `npm audit` and `npm audit --omit=dev` in backend/ (the registry is the only external host contacted).

Not done: any request to Razorpay, Dodo, AI vendors, search providers or registers; a real browser; load testing; the end-to-end checkout (it needs the provider's order API, so quote, checkout and idempotency were reviewed in code and the payment-state paths were driven by inserting rows and sending signed webhooks). ## What was checked and found sound

Evidence is the test or the code line; "tested" means run against the live server.

Admin authentication
- Comparison (server.js:1459-1506): both credentials are hashed with SHA-256 and compared with `timingSafeEqual`; both comparisons are evaluated before branching; split on the first colon only. Tested: no header, wrong password and empty credentials all return 401.
- Unset credentials fail closed (tested with an empty environment, including `-u :` and `-u undefined:undefined`): 503 on every `/api/admin` route.
- Every admin route is registered after `app.use('/api/admin', adminLimiter)` (server.js:290) and carries `adminAuth`; the purge route is included. (The limiter's weaknesses are SHEL-34 and SHEL-35.)
- Admin pages escape output: `esc()` in admin.html covers `& < > " '` and is used for disputes, replies, contact and finding text (lines 456-480); no raw `innerHTML` with dispute or reply text.

Access tokens and quotes
- Token (engine/access.js): HMAC-SHA256 over the payload, timing-safe compare, tied to one ref, expiry checked. Code read; the valid-token path was exercised against the live server (SHEL-38, SHEL-41), forged-token cases were not run.
- Quote (pricing/quote.js): signature over id, ref, country, currency, gross, tax, price-book version and both timestamps; timing-safe compare; 30 minute expiry; status checks for superseded and used. The charged amount is the stored quote's gross, never a number from the browser (server.js:431).
- Quote ids are 80 bits (`q_` plus 20 hex), ref and purchase ids are UUIDs or 48-bit refs; none is sequential.

Webhooks
- Razorpay: raw-body HMAC, hex-only, equal-length, timing-safe (engine/razorpay.js:46-57). Tested on the live route: valid 200; one-nibble change, extra bytes, empty and non-hex signatures all 401; a different body with the same signature 401.
- Dodo (engine/mor.js:77-87): Standard Webhooks id.timestamp.body signed content, 5 minute tolerance either side, constant-time compare, multiple signatures accepted. Tested on the live route: valid 200, replay of the same id returns `duplicate`, 10 minutes stale 401, 10 minutes in the future 401, wrong signature 401, signature for a different id 401, second signature good 200, no headers 401. Amount and currency must equal the stored purchase or nothing unlocks (server.js:924, 970).
- Razorpay checkout verification uses the order id stored on the server, not the browser's (server.js:887-889). The Razorpay webhook has no timestamp to check (the provider does not send one); replay is stopped by the event table.
- (Failure modes of these handlers are SHEL-36, SHEL-37, SHEL-32.)

HTTP surface
- Helmet defaults plus an explicit CSP: `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, Razorpay origins only for script, frame and connect. HSTS, nosniff, COOP, CORP same-origin, no X-Powered-By. `script-src` and `style-src` include `'unsafe-inline'` (documented in the code; it also means `javascript:` links execute, SHEL-40).
- CORS in production with an unlisted origin returns 403 and processes nothing (tested). Browsers send Origin on cross-origin POSTs, so cross-site form posts to admin routes are refused. (Fail-open outside production: SHEL-43.)
- Error handler (server.js:1581) returns a fixed message and never a stack or database text; seen on the 500 responses I inspected (purge, developer-response, webhook, admin). Provider errors are logged without keys (mor.js comment and code, razorpay.js messages carry only the status).
- SQL: `grep` for template-literal SQL with interpolation in server.js, engine, payments and pricing finds none; all queries are parameterised.
- No `Host` header use, no `express.static`, no file path built from request data except `loadSample` (regex `^[a-z0-9-]{2,40}$`) and fixed guide file names. `/samples/:id`, `/r/:ref` and the 404 pages contain no request data.
- PDF route `/r/:ref/pdf` needs a valid token (403 otherwise); filename is sanitised to `[A-Za-z0-9-]`; renders are capped by PDF_CONCURRENCY (default 2) with a queue; one context per render, closed in `finally`. Sample PDFs are cached per id, and ids are validated.

Report pages and stored content
- With every string in the three sample reports poisoned with `<img onerror>` and `<script>`, the full report, preview, working page, preview with price and sample page contained no raw markup (the one raw hit, `class="st-${f.status}"`, takes a value set in code: dossier.js statusOf).
- Disputes (note, contact) and developer replies are stored as text, shown to admins escaped, and shown to the public through `textContent` (shelterkart-frontend.html:4881-4882); the public JSON never includes the sender's address. Replies are never auto-published.
- `isOfficial()` (dossier.js) is anchored on the parsed hostname: `maharera.maharashtra.gov.in.evil.com`, a path or query containing the domain, userinfo tricks and `evilgov.in` are all not official.

Egress guard (connectors/egress.js)
- Tested and refused: userinfo (`https://example.com@127.0.0.1/`), literal IPs in decimal and hex, `[::1]`, `example.com.evil.com`, `evilexample.com`, `http:` and `file:` schemes. Redirects are followed manually and re-validated at each hop (max 3), method and body apply to the first hop only, caller headers are dropped when the host changes. Allow-list suffix matching is by label. (Gaps: SHEL-44.)
- The server fetches only registry hosts through the guard; every other outbound call goes to a fixed vendor URL (Razorpay, Dodo, AI vendors, delivery providers). Connector query strings use `encodeURIComponent`.

Secrets and logging
- `git grep` for key shapes (Anthropic, OpenAI, AWS, Razorpay, whsec, Google, GitHub, Slack tokens, private keys) finds nothing. `.env`, `backend/.env`, `backend/.env.first-run`, `backups/` and `backend/data/live-jobs/` are ignored. `.env.example` has empty secret values.
- Logging: no request bodies, tokens, keys or contact details are written by `console.*` calls; delivery log entries mask e-mail and phone; analytics is documented and coded to store no IP or user agent (daily-rotating salt, hash only; code read, not tested). (Retention of saved jobs: SHEL-42.)

Dependencies
- `npm audit` and `npm audit --omit=dev`: 0 vulnerabilities (info 0, low 0, moderate 0, high 0, critical 0). 87 production dependencies, 1 optional, 0 dev. Installed: express 4.22.3, cors 2.8.6, helmet 7.2.0, express-rate-limit 7.5.1, dotenv 16.6.1. Newer majors exist (express 5.3.0, helmet 8.3.0, express-rate-limit 8.7.1, dotenv 18.0.9); none is needed for a vulnerability. Nothing to update for security today.

## Suspected findings (not confirmed, not filed)

1. Quote reuse race. `verifyQuote` and `setQuoteStatus('used')` are separate steps (server.js:379, 427); two concurrent checkouts with the same quote and different idempotency keys could both pass and create two purchases for one quote. Needs the provider order API to test. Likely harmless (same amount, same buyer), possible double charge on a client bug.
2. Refund race. `refundPurchase` reads `refundedTotal`, calls the provider, then writes the refund row, with no lock (payments/refunds.js). Two concurrent admin refunds could both pass the local check; the provider would normally reject an over-refund. Admin-only.
3. Idempotency keys are global, not scoped to a ref or quote (server.js:349): a key reused with a different ref returns the earlier purchase's order. Keys are client-generated random strings; exploitation needs another buyer's key.
4. Prompt injection from fetched pages: the live pipeline relies on the one-line prompt rule, the fixed reply shape, citation checks against retrieved pages and code-decided marks. Layers 1 to 4 of connectors/untrusted.js (`encloseUntrusted`, `buildExtractionPrompt`, `validateShape`, `verifyGrounded`, `corroborationPolicy`, `processExtraction`) are not called from anywhere outside tests (`grep`): only `scanForInjection` is used (grounding.js:115 on titles and snippets, documents.js:71 on extracted fields). The detector missed 5 of 7 paraphrases tried (it caught "Ignore all previous instructions" and "SYSTEM NOTE for the AI"; it missed "Pay no attention to what you were told before", a leetspeak form, a French form and a polite-instruction form). Findings are free text inside the shape, so a page can still plant a false but cited claim. `project.developer_site` is model output that decides the "developer's own claim" status and the "from the developer's domain" label on public replies. Could not be tested without a live engine.
5. Chromium PDF rendering (engine/pdf.js) uses `setContent` with JavaScript and network enabled. It is safe only because every field is escaped (verified by fuzz). If an escape gap appears, the renderer reaches the internal network without the egress guard. Hardening: `javaScriptEnabled: false` and route interception that aborts all requests.
6. Server-sent event connections on `/api/investigate/:ref/events` have no per-IP or global cap; each holds a socket until the job ends. Unauthenticated. Not tested under load.
7. Large unauthenticated bodies: document-check accepts 12 MB JSON (10 per hour per IP, bypassable, SHEL-35); webhooks accept 1 MB. Memory pressure under concurrency; not measured.
8. Proxy depth in the real deployment (SHEL-35) and the planned compose file (PR #3): the API port is published directly, and the database is published on the host with the password `dev`. Dev-only, but worth fixing before anyone copies the file.
9. Container build in PR #3 runs `npx playwright install` without a version in a tree whose `package.json` does not list playwright, so the browser version is whatever is latest at build time, and `require('playwright')` in pdf.js may not resolve at runtime. Supply-chain and functional question for that PR.

### SSRF guard (SHEL-44)

```js
const E = require('./backend/connectors/egress');
const http = require('http'), dns = require('dns');
for (const ip of ['::ffff:7f00:1', 'fe90::1', 'febf::1', 'fec0::1', '64:ff9b::7f00:1', '2002:7f00:1::1', '::127.0.0.1'])
  console.log(ip.padEnd(20), JSON.stringify(E.classifyIp(ip)));
(async () => {
  const srv = http.createServer((req, res) => res.end('INTERNAL-SECRET')).listen(4318, '127.0.0.1');
  await new Promise(r => srv.on('listening', r));
  const origPromises = dns.promises.lookup, orig = dns.lookup;
  dns.promises.lookup = async (h, o) => h === 'rebind.test' ? [{ address: '93.184.216.34', family: 4 }] : origPromises(h, o);
  dns.lookup = (h, o, cb) => { if (typeof o === 'function') { cb = o; o = {}; } return h === 'rebind.test' ? (o && o.all ? cb(null, [{ address: '127.0.0.1', family: 4 }]) : cb(null, '127.0.0.1', 4)) : orig.call(dns, h, o, cb); };
  const { response } = await E.guardedFetch('http://rebind.test:4318/', { allowSet: new Set(['rebind.test']), allowHttp: true });
  console.log(response.status, await response.text());
  srv.close();
})();
```

### Type-confusion fuzz (SHEL-31, SHEL-45)

For each body-taking route and each value in `[null, 1e308, -1, true, [], {}, ['a'], {a:1}, 'x'.repeat(100), '\u0000', {toString:1}, [[]], [{toString:1}], {valueOf:1,toString:1}]`, POST a JSON body with every known field set to that value (ref, query, location, market, note, contact, reportRef, findingText, responseText, contactEmail, idempotencyKey, quoteId, billingCountry, taxId, purchaseId, razorpay_payment_id, razorpay_signature, paymentId, file, mediaType, event, url, host, amount, reason, email, phone, country, lang, session, previousQuoteId, pow, languages), with a random `x-forwarded-for` per request (SHEL-35), the admin Basic header on `/api/admin` routes, and a health check after each request that restarts the server and records the request when it is down. Result: 3 crashes, all on `/api/developer-response`; 500s on the routes listed in SHEL-45.
